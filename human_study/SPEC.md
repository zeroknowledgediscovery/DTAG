# Human study protocol contracts, version 1

This package is isolated from the simulator. It serves an anonymous, single-session, non-payment pilot. The initial observed state consists only of common baseline responses; no prose persona is decoded. A human accepts an immutable, server-selected question by selecting exactly one configured native category. Optional nonresponse is an observation with a separate reason and never a native category. Timeouts never become observations. Every accepted answer remains in the state; no capacity eviction applies.

The protocol is consent → common baseline (13 in the native draft builder; configurable) → transactional uniform assignment to right/left/neutral/random → up to 20 adaptive questions → common held-out outcomes → archived receipt. The fixture bank has four outcomes; the native draft proposes three. An empty eligible pool ends the intervention early and logs the reason. Randomization occurs after baseline completion. It is unstratified; stratification is not implemented. Control and administrative items are excluded from adaptive selection, not automatically scored for payment.

All four arms use the identical configured eligible bank after excluding baseline/asked items, outcomes, pole-defining items, administrative/factual items under the existing opinion classifier, invalid/missing categories and ethics exclusions. Right maximizes expected index displacement, left minimizes it, neutral minimizes its absolute value, random is uniform over sorted eligible items. Ties use ascending native ID. Selection uses the existing exhaustive one-step geometry, including its exact incremental native evaluator. Probabilities are normalized over the reviewed offered categories (missing categories excluded); this is an assumption requiring scientific review. PCG64 state is persisted before presentation. Model-predicted displacement and observed conditional-index displacement are distinct fields. Neither is called belief change.

Each selected intervention item takes the existing `dtag_core.llm_craft_survey_question` route and existing lexical-plus-LLM mapping route (`optimizer.dtag_bridge.map_question`, k=1). It must map to exactly the selected item. Two attempts are permitted, then the original canonical wording is presented with fallback metadata. The core itself can silently return canonical text on provider failure; this adapter explicitly flags any canonical return as a possible fallback. It records attempts, mapper hits, exact text/options, provider/model and prompt version. Prompt source hash and code/model/map/pole/native-binary hashes are captured. No extra variables are inferred from an answer. Baseline and outcomes use canonical common wording. The local computational fixture is a separate UI development mode, never enabled outside local/mock mode.

Question IDs are deterministic hashes of anonymous session, phase, position and variable. A CAS generation claim precedes external LLM work. Rendered wording is committed before delivery and exported before the question becomes available. Concurrent requests see the persisted question or a preparation status. A crashed generation worker's 150-second lease can be reclaimed; only unpresented generation can be repeated. Generation has two attempts and provider timeout/retries are bounded. No external calls run inside retryable Firestore transactions.

The repository uses atomic revision compare-and-set for session plus question/event/idempotency/outbox documents. Firestore is authoritative operational state. Each accepted answer creates a mandatory export obligation. GCS uses create-only generation preconditions, CRC32C verification, content hashes and exact-byte comparison on pre-existing objects. Advancing requires all export obligations committed. The next current/retry request reconciles failures between these operations. Finalization writes `final.json` only after earlier obligations are committed and exposes the receipt only after final export commitment. Research data remain private in GCS; investigator export uses ADC in a local CLI. The application has no arbitrary file/model/policy/secret input or researcher/debug endpoints.

Cookies use HMAC-SHA256, HttpOnly, Secure and SameSite=Strict outside local mode. Browser writes require same Origin, JSON and a 4096-byte body limit. Signed session IDs are random anonymous UUIDs. A request ID/PID supplied by a browser is never authentication. Basic per-instance throttling and Cloud Run caps bound accidental abuse, but do not constitute robust distributed bot prevention or a financial spend guarantee. No Prolific linkage or payment integration is implemented. Deploy into an isolated project because Firestore IAM is broader than individual study collections. Consent wording, data retention/deletion, participant support contact, eligibility, and an approved instrument remain investigator responsibilities before any recruitment.

Native model `gss/gss_2024` comes from the existing checksum-verified v0.2.1 public release. Exact categories and map coverage are validated at initialization. The native builder refuses to guess when required baseline/outcome items are absent or unsuitable. A predictive phenotype is a set of conditional predictions with uncertainty; a persona class is an external construct; the scalar pole-relative index is a model geometry statistic. This implementation validates computation and persistence, not construct validity, instrument sufficiency, ethics approval or human ideological effects.
