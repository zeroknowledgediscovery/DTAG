# GSS 2024 human-study wording: source-grounded generation (v2)

The native DTAG adaptive selector, model geometry, learned participant
state, scoring objective, native answer encodings and eligibility are unchanged.
The following process begins **only after** the native selector chooses a
variable. It does not create a fixed question bank.

## Evidence packaged into production

The Git-tracked `human_study/data/gss_2024_r2_source_context.json` contains
**781** release-2 codebook variable labels and interviewer notes,
extracted through the complete **811-variable** model-backed audit. Each
entry retains original PDF page numbers. The remaining 30 variables have
no matched release-2 entry, and the prompt explicitly states that source
context is unavailable for those. The audit is not a certification of
all question stems, skip conditions or response mappings.

The source catalog is reproducibly generated by
`human_study/scripts/build_gss2024_source_catalog.py` from the
`--codebook` version of `audit_all_native_gss_2024.py`.
Its canonical documentation is the NORC GSS 2024 release-2 codebook.

## Question generation

For the selected variable, `grounded_generation.py` supplies the language
model with:

- Native model variable ID (internal, never participant facing)
- Original 2024 semantic map description
- The best reviewed standalone wording contract, when one exists
- Its retrieved official codebook entry and page numbers, when available
- The **full native response alphabet**, with no 15-choice truncation
- Exact validation findings from the previous rejected draft, on retry

The new structured JSON output is
`{question: str, missing_context: bool, missing_details: str}`.
Unlike the shared DTAG webapp paraphrase prompt, human-study generation
allows multi-sentence questions and mandates visible options/anchors
when a response list, showcard, income bracket or conditional ordinal
would otherwise be missing.

For any question with a required external response list or large
categorical alphabet, deterministic validation checks that every native
alternative is actually shown. Existing source-specific validators still
check non-obvious referents and scale meanings. Unknown context is a
hard failure, not permission to invent a referent. On a validation error
the second attempt receives the *specific* missing-options or referent
diagnosis rather than an identical prompt. Any recognized complete
source-contract fallback remains available, preserving the current
provenance and archival behavior.

## Scope / limitations

- **No native variable is excluded because its source contract is missing.**
  The preexisting study service can move to another ranked item if a
  particular selected question cannot be rendered. This is a visible,
  journaled question-generation failure and not an alteration of
  LSM scoring.
- Full source coverage is **781/811 codebook entries**, not verified
  781/811 participant questions. Some original question stems depend
  on interviewer screens absent from the codebook label alone.
- LLM self-reported `missing_context` is useful but not a complete
  scientific validity test. The generic validator cannot prove every
  uncontracted question's construct fidelity; further source auditing
  and full-length live study QA remain necessary.
- This version adds no independent second LLM judge; validation is
  deterministic to avoid yet another OpenAI round-trip. Prompt length
  may increase generation latency; measure it rather than assuming
  the old 18-second transition time is unchanged.
- The existing native webapp `dtag_core.llm_craft_survey_question`
  helper remains unmodified; the human study uses a separately
  versioned generation prompt.

## Verification

```bash
git switch experiment/prolific-human-study
git pull --ff-only origin experiment/prolific-human-study
bash human_study/scripts/check_v3.sh
```

A dedicated test suite,
`human_study/tests/test_grounded_question_generation.py`,
verifies complete 26-category earnings ranges, contextual corrective
retries, conditional third-race questions, source-missing failures,
correct multi-sentence vignettes and production packaging of the
781-entry source catalog. The whole existing parity/Prolific suite
also runs in CI.

**Deployment is separate.** Source changes do not modify Cloud Run
until the reviewed study is redeployed from a clean checkout.
